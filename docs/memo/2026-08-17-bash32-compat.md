# Bash 3.2 互換化に伴う処理削除(`set +e` / `set -e` の切り替え、Bash 4.0+ 専用構文)

- **日付**:2026-08-17
- **分類**:処理削除(グローバル errexit の切り替え)、構文の置き換え
- **対象**:`scripts/generate_minutes.sh` の `invoke_claude` / `run_step` / `transcribe_part` / `find_input_files` / `build_step_input` / `ensure_transcript` / `validate_step`

## 内容

macOS 標準の `/bin/bash`(3.2.57)で `./scripts/generate_minutes.sh <project> <date>` が `${ext,,}: bad substitution` で即座に失敗していた。Bash 3.2 を最低サポートとする方針([01-conventions.md §8](../design/01-conventions.md))を確定し、以下を変更した。

### 削除した処理:`set +e` / `set -e` によるグローバル errexit の切り替え(3箇所)

| 箇所 | 削除前 | 削除後 |
|---|---|---|
| `invoke_claude` | `set +e` → `claude` 実行 → `status=$?` → `set -e` | `status=0` → `... \|\| status=$?` |
| `run_step` | `set +e` → `invoke_claude` → `status=$?` → `set -e` | 同上 |
| `transcribe_part` | `set +e` → `transcribe.py` → `status=$?` → `set -e` | 同上 |

**理由**:`invoke_claude` の末尾の `set -e` が、呼び出し元 `run_step` の `set +e` まで解除していた。その結果 `invoke_claude` の `return 3` の時点でシェルが即座に終了し、`run_step` の `die 3` に到達せず **`ERROR:` / `HINT:` が一切出ないまま終了コード3で落ちていた**(`claude` 失敗時・空出力時の全ケース)。`|| status=$?` は errexit を触らずに終了コードを取得できるため、握りつぶしにもならない([01-conventions.md §7](../design/01-conventions.md)、[02-generate-minutes.md §5](../design/02-generate-minutes.md))。

### 置き換えた構文(Bash 4.0+ 専用 → 3.2 互換)

| 箇所 | 削除前 | 削除後 |
|---|---|---|
| `find_input_files` | `ext="${ext,,}"` | `ext="$(printf '%s' "${file##*.}" \| tr '[:upper:]' '[:lower:]')"` |
| `build_step_input`(ステップ1分岐) | `mapfile -t memos < <(find_memo_files)` | `while IFS= read -r memo; do memos+=("$memo"); done < <(...)` |
| `ensure_transcript` | `mapfile -t media < <(find_media_files)` | 同じ while-read ループ |

`tr` は POSIX で macOS / Ubuntu 双方に標準で存在するため、依存パッケージの追加には該当しない。

### 分割した処理:`build_step_input` → `emit_step_sections` + `build_step_input`

Bash 3.2 のコマンド置換は `$( ... )` の中の `case` のパターン末尾 `)` を閉じ括弧と誤認するため、`case` を含む入力セクション生成部を `emit_step_sections` として独立関数に切り出した(`bash -n` では検出できず、実行時に `syntax error near unexpected token 'newline'` になる)。出力内容は変更していない([02-generate-minutes.md §4](../design/02-generate-minutes.md))。

### 修正した箇所:`"$min〜$max"` → `"${min}〜${max}"`

`validate_step` のメッセージ2箇所。UTF-8 ロケールでは `〜` のバイトが変数名の一部と解釈され、`min〜: unbound variable` で **`--from-step` / `--only-step` の値が不正なときにメッセージを出す前に落ちていた**(Bash のバージョンではなくロケール依存。C ロケールの devcontainer では再現しない)。

## 理由

`README.md` と `docs/requirements.md` 7.2 は macOS ホストを正式サポートとしており、`brew install` 対象に `bash` を含めていない。Bash 4+ を前提にする(= 追加インストールを必須にする)のではなく、スクリプト側を 3.2 互換に保つ方針を選んだ。

## 影響・代替

- 機能的な差分はない。`mapfile` も `|| status=$?` も前段コマンドの終了コードの扱いは同じ。
- 再発防止として静的検査(ケース34:Bash 4.0+ 専用構文、ケース34c:ブレース無し展開+非ASCII)と実行時検査(ケース34b:`/bin/bash` が 3.x なら通し実行)を追加した([07-testing.md §4](../design/07-testing.md))。
- **`bats` の実行のみ Bash 5 が必要**(bats 1.14 は Bash 3.2 上で日本語のテスト名を解決できず1件も実行されない)。パイプライン本体の実行には不要([01-conventions.md §8.3](../design/01-conventions.md))。
- 復元が必要な場合は `git show e873452:scripts/generate_minutes.sh` で変更前の実装を取り出せる。
