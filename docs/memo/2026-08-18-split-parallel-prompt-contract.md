# 分割並列実行に伴う運用プロンプトの契約変更と HINT 文言の変更

- **日付**:2026-08-18
- **分類**:運用時プロンプトの契約変更 / メッセージ文言の変更(コメントアウト・処理削除・依存変更には該当しない)
- **対象**:`projects/_template/prompts/*.md`(および `projects/sample/` と実プロジェクト `projects/{project-name}/` への反映)、`scripts/generate_minutes.sh` の `warn_if_input_too_large`

## 内容

`--parallel N` によるステップ1・2の分割並列実行([02-generate-minutes.md §9](../design/02-generate-minutes.md)、[requirements.md 3.2.8](../requirements.md))を追加したことに伴い、**運用時プロンプトの入出力契約を変更した**。プロンプトは非対話実行時の唯一の指示であり、スクリプト側の変更だけでは分割は成立しない(境界の重複を防ぐのはプロンプトの責務)。

| ファイル | 追加した契約 |
|---|---|
| `01_organize.md` / `02_structure.md` | ラベル `PART_INFO` / `CONTEXT_BEFORE` / `CONTEXT_AFTER` の説明。`## 分割実行(PART_INFO がある場合)` の節。`CONTEXT_*` の内容は**出力に含めない**(禁止事項へも明記)。`## 会議情報` は `part: 1/N` のときのみ出力する。担当範囲外を補完しない |
| `03_format.md` | `## STEP2_OUTPUT が分割実行の連結である場合` の節。同名・同主旨の `## トピック:` が複数回現れる場合は1つに統合する。重複する決定事項・ToDo・懸念事項は1行にまとめる |

`PART_INFO` が無い場合は従来と同一の指示になるよう、いずれの節にも「`PART_INFO` が無い場合は適用しない」を明記した(`--parallel` 未指定時の後方互換をプロンプト側でも保つ)。

`warn_if_input_too_large` の HINT は、`00_transcript.txt` を手で分割して個別に実行する案内から `--parallel N` の案内へ変更した(手作業の手順を案内し続ける理由が無くなったため)。

## 理由

- **`CONTEXT_*` を「出力禁止」と明示する方式を選んだ**理由:連結後の重複除去処理を実装しないため(重複判定はテキストの表記ゆれに弱く、決定的に書けない)。重なりを本体とは別ラベルで渡し、出力してはいけない範囲をプロンプトで宣言する方式にした([09-decisions.md](../design/09-decisions.md))。
- **`## 会議情報` を part 1 限定にした**理由:全パートが出力すると連結時に会議情報ブロックが N 個並び、ステップ3が会議概要を作れなくなる。
- **トピック統合をステップ3に置いた**理由:ステップ2は担当パートしか見ないため、境界で分断されたトピックを統合できない。会議全体を1回で読むのはステップ3のみである。

## 影響・代替

- **`--parallel` を使わない限り挙動は変わらない**。追加した指示はすべて `PART_INFO` の有無で条件付けられている。
- プロジェクト固有プロンプトは `projects/_template/prompts/` を正として反映した。`sample` は差分が今回の追加のみだったためテンプレートをコピーし、実プロジェクト(`詳細な議事録` セクション等の独自構成あり)は該当箇所のみ個別に編集した。**今後、独自構成を持つ `projects/{project-name}/prompts/` をテンプレートで上書きしてはならない。**
- 分割時の品質(境界での発言の欠落・重複、`CONTEXT_*` の混入)は決定的なコードでは検証できない。`/minutes-review` と人間レビューで担保する(CLAUDE.md §6 の方針どおり)。
- bats では stdin に `PART_INFO` / `CONTEXT_BEFORE` / `CONTEXT_AFTER` が正しい範囲で現れることまでを検証している([07-testing.md](../design/07-testing.md))。プロンプトへの追従漏れは検出できないため、ラベルを増減する際は3プロジェクト分のプロンプトを併せて更新する。
